1. Getting Started

Creating Your Account

  1. Open fintrack at https://fintrack.nudgelabs.app
  2. Click "Create an account" on the login page
  3. Enter your email and a strong password (10+ characters, including an uppercase letter and a number)
  4. Set up two-factor authentication (MFA) — choose TOTP app or Email OTP
  5. Scan the QR code with DUO, Google Authenticator, or Authy
  6. Enter the 6-digit code to verify setup — your dashboard loads
💡 Use DUO or Google Authenticator for the most secure MFA experience.

Logging In

  1. Enter your email and password
  2. Enter the 6-digit code from your authenticator app
  3. Your session expires after 30 minutes of inactivity — a 60-second warning appears before logout
💡 Click "Stay logged in" in the warning dialog to reset the session timer.

Forgot Your Password?

⚠️ Important: Due to fintrack's zero-knowledge encryption, your password is the key that encrypts all your financial data. There is no way to retrieve a forgotten password. Resetting your password will permanently and irreversibly delete all your existing transaction data. You will start with a completely fresh account. This cannot be undone.
  1. Click "Forgot password?" on the login page
  2. Enter your email — a reset link is sent (expires in 30 minutes)
  3. Click the link and set a new password
  4. Log in with your new password — your account will be empty and you will need to re-import your transactions

Lost Your Authenticator?

  1. On the MFA screen, click "Lost access to your authenticator?"
  2. Enter your email to receive a recovery code
  3. Enter the code plus your fintrack password
  4. Set up MFA again immediately after recovery

3. Importing Transactions

Downloading Statements from Your Bank

Each bank has a slightly different process for downloading CSV statements:

  • Chase (credit card): chase.com → Activity → Download icon → select CSV → choose date range
  • Chase (checking): chase.com → Activity → Download icon → select CSV. Note: the checking export has a different format from the credit card export (see section 4)
  • Citi: citibank.com → Account Summary → click account → Download or Export → CSV
  • Bank of America: bankofamerica.com → Statements → Download → CSV
  • AmEx: americanexpress.com → Statements & Activity → Download → CSV
💡 Download one year at a time per account. This keeps file sizes manageable and makes duplicate detection more reliable.

Importing a File

  1. Click "Import Data" in the sidebar
  2. Drop your CSV file or click to browse
  3. Select the CSV format (auto-detected from filename if named with bank prefix)
  4. Enter a card nickname — this is required and identifies the account (e.g. "Citi Shared 2025")
  5. Enter your fintrack password — used to encrypt your data before storage
  6. Click "Import files" — results show imported, duplicates, and skipped counts
💡 Use a consistent nickname for the same card across imports. The nickname is used to detect duplicates — importing the same file twice with the same nickname will show all duplicates and import nothing new.

4. Supported Formats & Column Layouts

fintrack auto-detects the CSV format based on your file's column headers. There are four supported layouts:

Format A — Separate Debit/Credit Columns

Used by: Citi, AmEx, Discover, Capital One

Header pattern: Date, Description, Debit, Credit

Debits (purchases) appear in the Debit column; payments and refunds appear in the Credit column. fintrack imports debits as expenses and skips credits (payments).

💡 Citi year-end exports sometimes include a 3–5 line summary preamble above the actual CSV header. fintrack automatically scans for the header row and skips any preamble.

Format B — Single Amount Column (Negative = Purchase)

Used by: Chase credit cards, Bank of America, Wells Fargo

Header pattern: Transaction Date, Post Date, Description, Category, Type, Amount

Purchases appear as negative numbers (e.g. -88.33); payments appear as positive numbers. fintrack flips the sign so expenses become positive, then skips credits.

Format C — Single Amount Column (Positive = Purchase)

Used by: Some regional banks and older export formats

Header pattern: Date, Description, Amount

Purchases appear as positive numbers. Credits and payments appear as negative numbers and are skipped.

Format D — Chase Checking Accounts

Used by: Chase checking and savings accounts

Header pattern: Details, Posting Date, Description, Amount, Type, Balance, Check or Slip #

This format is different from Chase credit cards. The Details column contains DEBIT or CREDIT. The Amount column is already signed: negative for debits (outflows), positive for credits (inflows). fintrack imports debits as expenses and skips credits (deposits, payroll, interest).

Known quirk: Chase checking CSV files include a trailing comma on every data row, creating an extra empty column. fintrack handles this automatically, but if you open the file in Excel and re-save it, Excel may strip the trailing comma, which is fine — fintrack handles both cases.

5. Import Tips & Best Practices

  • One year per file: Download and import one calendar year at a time per account. This keeps files manageable and helps you track what has been imported.
  • Consistent nicknames: Always use the same card nickname for the same account (e.g. always "Chase Shared" for your shared Chase card). Nicknames drive duplicate detection.
  • Duplicate safety: Re-importing the same file with the same nickname is safe — fintrack detects exact duplicates and skips them. You will see "0 imported, N duplicates" in the result.
  • File encoding: fintrack accepts UTF-8 and ASCII CSV files. If your file has unusual characters or won't import, open it in a text editor and save as UTF-8.
  • Date formats: Both MM/DD/YYYY and YYYY-MM-DD are auto-detected. No manual date format selection is needed.
  • Don't edit the CSV: Import the file exactly as downloaded from your bank. Editing in Excel can change date formats, remove trailing commas, or alter the encoding in ways that break the import.
  • Skipped rows: Some rows are intentionally skipped: credits (payments, refunds, deposits), zero-amount rows, and rows that cannot be parsed. The import result shows the exact count.
  • Multi-member households: If your CSV contains a "Member" or "Card Member" column (e.g. AmEx), fintrack automatically assigns transactions to the correct household member.

7. Categories & Reconciliation

How Categories Work

fintrack automatically categorizes transactions using keyword matching on the transaction description. Uncategorized transactions land in "Other". Aim to keep "Other" below 5% for meaningful analytics.

Fixing Uncategorized Transactions

  1. Click "Reconciliation" in the sidebar
  2. The page shows all transactions in the "Other" category
  3. Use the dropdown to assign the correct category and subcategory to each transaction
  4. Click "Save X changes" to apply all edits at once

Adding New Categories

  1. On the Reconciliation page, click "+ Add Category" (top right)
  2. Enter category name, subcategory, Essential/Discretionary flag, and color
  3. Click "Add Category" — it immediately appears in all dropdowns

12. Frequently Asked Questions

Why were some rows skipped during import?

fintrack is an expense tracker, so it intentionally skips rows that are not expenses. For credit cards, this means payments and refunds (credits) are skipped. For checking accounts, deposits, payroll, interest, and incoming transfers are skipped. The import result shows the exact count of skipped rows. Zero-amount rows are also skipped.

Why does my import show "0 imported, 0 duplicates"?

This usually means the CSV format was not recognized. Double-check that you selected the correct format for your bank, and that the file is the original CSV download (not edited in Excel). If the problem persists, contact us at nudgelabsllc@gmail.com with a sample of the file header.

What is the difference between Chase credit card and Chase checking formats?

Chase credit card exports use the header Transaction Date, Post Date, Description, Category, Type, Amount. Chase checking exports use Details, Posting Date, Description, Amount, Type, Balance, Check or Slip #. These are different formats (B and D respectively) and the correct one must be selected. fintrack usually auto-detects the right format from the column headers.

Can I import the same file twice?

Yes, safely. fintrack detects exact duplicates based on the card nickname, date, description, and amount. If all transactions in the file have already been imported, you will see "0 imported, N duplicates." No data is created twice.

Why are internal transfers showing as expenses?

Transfers between your own accounts (e.g. checking to savings, Zelle to yourself) appear as debits in your bank's CSV export. fintrack imports them as expenses because it cannot distinguish a transfer from a payment to someone else. You can recategorize these to "Transfers" on the Reconciliation page to keep your spending totals accurate.

What happens if I forget my password?

Because fintrack uses zero-knowledge encryption, your password is the only key to your data. If you forget it, you can reset your password using the "Forgot password?" link, but all your existing transaction data will be permanently and irreversibly deleted. You will need to re-import your bank statements. There is no way to recover the old data. We strongly recommend storing your password in a password manager.

Can two family members use the same account?

Yes. fintrack supports multi-member households. Import statements for different family members under the same account. If your CSV includes a "Card Member" column (e.g. AmEx), fintrack automatically assigns transactions to each member. You can also use the Members page to manage household members manually.

How do I delete my account?

Contact us at nudgelabsllc@gmail.com to request account deletion. All your data, including encrypted transactions, will be permanently removed from our servers.

Is my data backed up?

Your encrypted data is stored on AWS infrastructure with standard redundancy. However, since fintrack uses zero-knowledge encryption, we cannot recover your data if you lose your password. We recommend periodically exporting your data using the Export feature (available on Household and Premium plans) and storing the export securely.
